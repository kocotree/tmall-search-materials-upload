# 素材要求

## 新任务选图与完整坑位

- 每个提交商品至少需要 3 张预检通过、源 SHA-256 唯一的采用图片；1–2 张只能保存草稿。
- 自动完整坑位数为 `min(missing_materials, floor(N/3))`，每坑 3–9 张。
- 同坑必须全部可生成同一个 3:4 或 1:1 比例；确认坑位前不得写裁剪或压缩输出。
- 预检只读取采用图片，不扫描未采用的共享盘图片。

## 通用要求

- 原始文件只读；裁剪或转码结果写入独立派生目录。
- 每个文件记录来源系统、绝对路径、商品 ID、货号、授权状态和 SHA-256。
- 授权状态不是 `confirmed` 时使用 `LICENSE_UNKNOWN` 阻断。
- 零字节、无法读取、不支持的格式和重复指纹不得进入审核清单。
- 商品 ID 是首选匹配键，货号是后备键；名称匹配只能产生人工确认候选。

## 图文素材

- 每个图文坑位包含 3–9 张图片。
- 支持 JPG、JPEG、PNG 和 WebP。
- 接受 3:4 或 1:1；同一图文坑位不得混合比例。
- 3:4 建议达到 `1440×1920` 及以上；1:1 建议达到 `1440×1440` 及以上。尺寸是否阻断由运行时图片策略决定，不在素材匹配阶段提前分组。
- 比例容差由 `config/media-policy.example.yaml` 的运行时副本配置。
- 校验文件可读性、文件大小、宽高、比例、同组一致性、零字节、重复指纹和授权状态。

## 视频素材

运行时策略必须完整提供以下字段：容器格式、编码、最短/最长时长、最小分辨率、允许比例、最大文件大小、封面要求、水印规则。任何字段为空时返回 `VIDEO_POLICY_INCOMPLETE`，禁止自动发布视频。

视频元数据必须来自可信探测器或已验证素材清单，并至少包含编码、时长、宽、高、封面存在状态和水印存在状态。无法取得时返回 `VIDEO_METADATA_UNAVAILABLE`。

对应错误码包括：

- `VIDEO_FORMAT_INVALID`
- `VIDEO_CODEC_INVALID`
- `VIDEO_DURATION_INVALID`
- `VIDEO_RESOLUTION_INVALID`
- `VIDEO_ASPECT_RATIO_INVALID`
- `VIDEO_SIZE_INVALID`
- `VIDEO_COVER_MISSING`
- `VIDEO_WATERMARK_NOT_ALLOWED`

## 当前生产门禁

`config/media-policy.example.yaml` 中的视频字段故意保持为空，表示当前生产规格尚未由用户确认。在用户用官方后台规则补齐运行时配置前，图片任务可以继续预检，视频任务必须保持 blocked；不得用猜测值替代。
# 图片合规与裁剪要求

- 支持格式：JPG/JPEG、PNG、WebP；损坏、零尺寸、不可读取或不支持格式为 `unusable`。
- 允许发布比例：3:4、1:1，比例容差由运行时策略配置。
- 最小发布尺寸：宽度和高度都不少于 720px。判断可裁剪素材时按各目标比例的最大内接结果计算，不只看原图宽高。
- 推荐尺寸：3:4 为 1440×1920 及以上，1:1 为 1440×1440 及以上。低于推荐尺寸是警告，不禁止第三阶段选择。
- 文件大小范围：`200×1024` 至 `20×1024×1024` 字节，边界值包含在允许范围内。小于 200KiB 为 `IMAGE_SIZE_BELOW_MINIMUM` 并禁止采用；超过 20MiB 时只有 Pillow 压缩可用才允许进入第四阶段，否则为 `COMPRESSION_UNAVAILABLE`。
- 每个坑位 3–9 张，同一坑位不可混合 3:4 与 1:1；不要求一次填满后台全部空坑位。
- 人工裁剪初始框使用目标比例的最大内接居中矩形。用户可移动、缩放；裁剪框不得越界、不得改变目标比例。
- 派生图使用策略中配置的输出格式和质量，写入当前任务的 `04-image-review/derived/`。共享盘源图始终只读。
- 第四阶段只记录 `candidate|excluded` 及两个比例的候选裁剪框，不生成 `direct/crop/compress` 正式输出。唯一比例和处理动作由第五阶段已确认坑位决定。
- 图片压缩使用 Pillow 本地实现，按策略质量范围搜索并在必要时等比例缩小；不得低于最小尺寸，也不得通过无意义填充把小文件伪装为合规。正式输出仅写入当前任务 `05-slots-copy/derived/`。主体感知 AI 裁剪仍只有 Codex Agent 交接接口，最终裁剪框须人工确认。
- Codex 坑位建议只读取当前任务受控缩略图。解析顺序为当前请求缓存、第四阶段预览缓存、第三阶段预览缓存，最后才只读尝试共享盘原图；缓存与源图都不可用时返回 `AGENT_THUMBNAIL_UNAVAILABLE`。请求缩略图必须复制/重编码到 request 目录，并同时记录源身份 SHA-256 与缩略图 SHA-256。
- AI 方案只能建议同商品、统一 1:1 或 3:4、3–9 张唯一图片及顺序。用户“采用”只把方案写入坑位草稿；正式裁剪和压缩仍由用户点击“确认计划并处理图片”后执行。
## 坑位确定后的处理边界

- 第四阶段只计算 1:1、3:4 可行性、默认最大内接框和处理预估，不生成正式文件。
- 第五阶段先由 AI/人工确定每坑唯一比例和 3–9 张有序图片，再开放该 `slot_id + target_ratio` 的人工裁剪。
- 用户可接受默认框或输入调整后的归一化裁剪框；需要压缩的图片必须单独确认。处理接口重新校验源 SHA-256，派生文件只写任务目录。
- 同一坑位不得混用 1:1 与 3:4。比例、图片、顺序或裁剪框变化后旧输出及其文案身份失效。
