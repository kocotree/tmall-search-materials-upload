# Playwright 后台流程

## 会话与配置

- 用户自行登录天猫并处理验证码、短信、扫码和风控。
- CLI 通过运行时 `--cdp-url` 连接用户已启动的 Chromium 会话；不持久化会话秘密。
- 每次导出、补采和发布前读取页面可见店铺名，必须与目标店铺完全一致。
- 生产选择器通过版本库外的 YAML 文件传入。缺少任何必需键立即停止。

## 导出

1. 为本次任务创建独立时间戳目录；输出目录必须不存在或为空。
2. 导出前读取页面可见店铺名并与目标店铺精确匹配，同时检测验证码、扫码和风控页面。
3. 用 `--report basic|promotion|both` 分别触发基础素材和推广素材下载；一次任务每种报表只接受一个文件，不从公共下载目录猜测“最新文件”。
4. 按 `run_id` 和报表类型保存到 `basic/` 或 `promotion/` 子目录，记录原始文件名、下载时间、SHA-256、数据行数和 schema 校验结果，不覆盖历史批次。
5. 写入 `source-files.json` 与 `export-manifest.json`。清单保存准确店铺、商品状态筛选条件、报表状态和原因码。

基础素材 XLSX 必须校验 `商品ID`、`商品标题`、`商品白底图`、`短标题`（或标准化别名）。Excel 可见空单元格按缺失处理，不得把底层样式或读取工具的展示值当作业务值。

推广素材内部兼容旧称“搜推素材”，最低校验 `商品ID` 和 `素材类型`。当前推广字段契约为 `draft`：即使下载和最低 schema 校验通过，在确认目标 3/9 坑、坑位号、远端素材 ID、审核状态和空坑表达方式前，也不得据此自动判定完整或进入生产批准。

## 补采

只处理 eligibility 为 eligible 且导出无法确定缺口的商品。按精确商品 ID 搜索，读取目标 3/9 坑、现有素材数、空坑位和审核状态。素材表容器或字段不存在时返回 `SELECTOR_INVALID`：商品 eligibility 保持 `eligible`，受影响坑位进入 `needs_manual_review`，未知字段保持未知。

## 发布

1. 验证 manifest schema、总哈希、有效期和目标店铺。
2. 重算当前 item 的媒体、标题、描述、动作和坑位内容。
3. 精确搜索商品 ID，核对页面商品和目标空坑位。
4. 根据批准类型选择图文或视频，上传批准文件并填入批准文案。
5. 点击发布一次，记录时间和页面证据。
6. 返回列表或详情页，核对远端素材 ID、坑位、指纹、提交时间和审核状态。

发布后超时或成功信号/远端 ID 缺失时进入 `publish_uncertain` 并暂停批次。禁止再次点击发布；先执行远端核验。

## 选择器原则

优先 `data-testid`、稳定 `data-*`、固定字段属性和 ARIA role/label。禁止用屏幕坐标作为常规实现。页面变化只修改 Page Object 或运行时配置，不把选择器写入业务规则。
