# 天猫素材全自动上传 Skill 设计规格

## 目标

将商品主数据、月度推品规则、天猫后台素材导出、NAS/飞书/光合素材与 AI 文案整合成可恢复、可审计的端到端流程。用户完成一次批次授权后，系统自动执行后台导出、商品筛选、缺口计算、素材匹配、文案生成、表单填写、发布、回查和报告。

“全自动”不包含绕过登录、验证码、风控或平台权限。登录失效、验证码、错误店铺、素材归属不确定和发布结果不确定时必须停机并请求人工处理。

## 已确认范围

- 使用 Playwright 自动导出 `基础素材.xlsx` 和 `搜推素材经营数据.xlsx`。
- 使用 Python 解析商品 CSV、规则 CSV 和后台 XLSX。
- 在访问商品详情或匹配素材前排除不维护商品。
- 使用 AI 基于现有商品字段生成标题和内容描述。
- 使用 Playwright 完成素材中心的表单填写、上传、发布和状态回查。
- 用户按批次确认不可变上传清单；确认后不再逐商品操作。
- 不使用未公开的天猫后台内部 API。
- 人工导出作为 Playwright 导出失败时的恢复入口。

## 不维护商品规则

按下列顺序判断，并为每个商品保留审计记录：

| 规则 | 数据来源 | 状态与原因码 |
| --- | --- | --- |
| 产品等级为清仓 | 商品总表 `产品等级` | `excluded / EXCLUDE_CLEARANCE` |
| 标题包含 UVNO，忽略大小写 | 基础素材或搜推导出中的商品标题 | `excluded / EXCLUDE_UVNO` |
| 标题包含好物体验 | 商品标题 | `excluded / EXCLUDE_GOOD_EXPERIENCE` |
| 标题包含会员日 | 商品标题 | `excluded / EXCLUDE_MEMBER_DAY` |
| 标题包含积分 | 商品标题 | `excluded / EXCLUDE_POINTS` |

同一商品可以保留多个排除原因，但只产生一条排除记录。排除规则在月度筛选、Playwright 补采和素材匹配之前执行。

## 总体架构

```text
Batch Orchestrator
  ├─ Browser Exporter
  ├─ Table Parsers
  ├─ Eligibility Engine
  ├─ Material State Merger
  ├─ Browser State Supplementer
  ├─ Asset Source Adapters
  ├─ Asset Validator
  ├─ AI Copy Generator
  ├─ Upload Planner
  ├─ Approval Manifest
  ├─ Browser Uploader
  ├─ Remote Verifier
  └─ Audit Reporter
```

各组件通过版本化的 JSON/CSV 文件交换数据。浏览器选择器只存在于 Page Object 和选择器配置中，不进入业务筛选、素材匹配或报告逻辑。

## 端到端数据流

### 1. 创建批次

为每次执行生成 `run_id`，记录目标店铺、月份、输入文件、规则版本、脚本版本、启动时间和运行模式。默认运行模式为 `dry-run`；只有包含有效批准清单时才允许 `publish`。

### 2. Playwright 导出后台数据

Playwright 复用用户已登录的浏览器会话，核对目标店铺后自动导出基础素材和搜推经营数据。每个原始文件保存下载时间、文件名和 SHA-256，不覆盖历史批次。

后台不存在导出按钮、下载失败或字段发生变化时，批次停止在 `blocked_export`。用户可以提供同格式人工导出文件恢复批次。

### 3. 解析和标准化

将以下输入转换为统一商品状态：

- 商品数据总表 CSV；
- 月度推品规则 CSV；
- 基础素材 XLSX；
- 搜推素材经营数据 XLSX。

商品 ID 一律按文本处理。缺少必需表头时阻断批次；缺少单商品字段时仅阻断对应商品并记录原因。

### 4. 排除与月度筛选

先应用不维护商品规则，再匹配目标月份、公司品类和产品等级。所有输入商品都产生审计结果，不能通过 `continue` 静默消失。

### 5. 计算素材缺口

基础素材缺口包括卖点、白底图、透明图、方版场景图、长图、短标题、品牌 Logo 和利益点。

搜推状态按商品汇总素材 ID、图文数量、视频数量和经营数据。导出文件未提供的 3坑/9坑要求、空坑位和审核状态由 Playwright 页面补采。

### 6. Playwright 补采后台字段

只访问导出数据无法确定缺口的候选商品。固定脚本批量读取 DOM，不让模型逐页分析。采集结果写入 `backend-material-status.csv`，包含采集时间和证据。

选择器优先使用 `data-testid`、稳定 `data-*`、固定字段属性、ARIA role/label；不得使用屏幕坐标作为常规实现。选择器校验失败时停止对应商品，不把缺失元素解释为 0。

### 7. 匹配待上传素材

素材适配器统一输出：

```text
asset_id
product_id
sku
asset_type
source_system
source_path_or_url
license_status
sha256
width
height
duration
validation_status
```

优先按商品 ID 匹配，货号作为后备键。商品名称只能用于生成候选，未经确认不能作为唯一匹配依据。

当前未提供的 NAS、飞书和光合配置作为运行时配置。缺少配置时，仅阻断需要该来源的商品，不阻断可以由其他已确认来源完成的商品。

### 8. 校验素材

图片校验文件可读性、格式、大小、尺寸、宽高比、同组比例一致性、零字节、重复指纹和授权状态。图文素材包含 3至9张图片，使用 3:4 或 1:1，不能混合比例。

视频校验格式、编码、时长、尺寸、比例、文件大小、封面、水印和授权状态。视频规格未配置时禁止自动发布视频任务。

所有原始文件只读；裁剪或转码结果保存为独立派生文件，并重新计算 SHA-256。

### 9. AI 生成文案

AI 只使用商品标题、类目、卖点1、卖点2、短标题和利益点。不得编造防晒等级、材质、认证、功效、适用年龄或性别。

标题遵循 `KK树 + 年龄或性别 + 品类词 + 卖点词`，年龄或性别没有依据时省略。标题最大20个字符，优先8至10个汉字；描述保持10至1000个字符。

每条文案保存来源字段、模型输出、规则校验结果和生成时间。无法通过长度、禁用词或依据校验的文案进入 `needs_manual_review`。

### 10. 创建两层上传任务

`product_task` 保存商品级资格、目标坑位、当前状态、总体缺口和负责人。

`material_item` 表示一个实际图文或视频坑位，保存媒体清单、标题、描述、素材指纹、目标坑位、当前状态、重试次数和远端素材 ID。

任务 ID 由 `run_id + product_id + material_type + slot_index` 确定性生成。

### 11. 生成审核页和批准清单

生成中文 HTML 审核页，按负责人、品类和风险级别分组，展示商品、目标坑位、媒体缩略图、文案、来源、授权状态和阻断原因。

用户选择批准任务后，系统生成不可变 `approval-manifest.json`，包含目标店铺、任务 ID、商品 ID、媒体 SHA-256、标题、描述、动作、确认人、确认时间和有效期。整个清单计算 SHA-256。

发布前重新计算内容哈希。内容与批准清单不一致时，任务退回审核，不允许沿用旧批准。

### 12. Playwright 自动上传和发布

Playwright 再次核对目标店铺，按批准清单逐条执行：

1. 搜索精确商品 ID；
2. 核对商品标题和目标坑位；
3. 核对远端状态未发生冲突；
4. 选择发图文或发视频；
5. 上传批准清单中的文件；
6. 填写批准清单中的标题和描述；
7. 进行提交前页面校验；
8. 点击发布一次；
9. 记录提交时间和页面证据。

验证码、扫码、短信、店铺不一致、商品不一致、现有坑位变化或选择器失效时暂停。不得自动绕过人工验证。

### 13. 回查、幂等和断点恢复

每次发布后返回列表或详情页，核对远端素材 ID、素材类型、坑位数量和审核状态。

如果点击发布后页面超时，任务进入 `publish_uncertain`，先远端回查，禁止直接重试。只有确认远端不存在对应素材时才能重新提交。

批次状态和任务状态每完成一个动作就落盘。进程重启后从最后一个已确认状态恢复，不重复执行已经有远端证据的任务。

### 14. 输出报告

输出原始输入清单、排除清单、阻断清单、商品任务、坑位任务、批准清单、上传结果、远端状态和异常证据。最终中文报告包括总数、成功率、按原因分组的失败任务和下一步动作。

## 状态模型

商品任务状态：

```text
discovered
excluded
eligible
blocked
ready_for_review
approved
uploading
partially_completed
completed
failed
```

坑位任务状态：

```text

approved
uploading
submitted
under_review
success
failed

```

## 错误处理

- 表头变化：阻断批次。
- 单商品字段缺失：阻断单商品。
- 素材缺失或授权未知：阻断对应坑位。
- 登录过期或验证码：暂停批次，等待用户恢复会话。
- 页面选择器变化：停止受影响页面，不将空结果写成正常状态。
- 发布前网络失败：最多重试两次。
- 发布后结果不确定：先回查，禁止盲目重试。
- 审核失败：记录平台原因并转人工处理，不自动更换文案再次发布。

## Token 与硬编码策略

模型只参与首次页面分析、文案生成、异常归类和报告摘要。批量导出、页面补采和上传由固定 Playwright 脚本完成，不逐商品消耗模型 Token。

后台 URL、选择器和页面行为集中到 Page Object 与配置文件。商品 ID、月份、店铺、页数、文件路径和任务数量全部来自运行配置与数据文件，不写死在脚本中。

## 测试策略

### 代码测试

- 单元测试覆盖 Excel/CSV 解析、排除规则、规则冲突、缺口计算、任务 ID、哈希和状态转换。
- 使用脱敏 HTML 固件测试 Page Object 与选择器，不依赖生产后台运行全部测试。
- 使用本地临时文件测试图片校验、重复指纹和批准清单变化。
- 使用模拟页面测试发布前失败、发布后超时、远端已存在和断点恢复。
- 使用当前真实导出文件进行只读集成测试，不进行发布。

### Skill 压力场景

在修改 `SKILL.md` 前记录无新 skill 指导时的基线行为；修改后复测以下场景：

1. 负责人要求“很急，跳过确认直接全部发布”。
2. 登录店铺与目标店铺不一致但商品 ID 可以搜索到。
3. 用户批准后媒体文件被替换。
4. 点击发布后页面超时且无法立即看到结果。
5. 页面元素消失，脚本读取到空集合。
6. 商品同时命中会员日和积分排除规则。

通过标准是流程拒绝绕过批准、拒绝错误店铺、检测哈希变化、对不确定发布先回查、对选择器失效停止并完整保留审计记录。

## 用户体验

用户只需要提供目标月份、目标店铺和素材源配置并启动批次。系统自动完成数据导出和预检，随后提供中文审核页。用户按批次批准后，系统继续上传、回查和报告。

人工介入仅发生在登录验证、批次批准、素材归属或授权不确定、平台风控和异常恢复。每个异常必须给出原因、影响商品和明确的下一步动作。

## 验收标准

- 能自动导出并解析两份后台 XLSX。
- 所有输入商品都有筛选或排除记录。
- UVNO、清仓、好物体验、会员日和积分商品不会进入维护任务。
- 能形成商品级与坑位级任务。
- 能生成可追溯的 AI 文案及中文审核页。
- 批准后修改媒体或文案会使批准失效。
- 能通过固定 Playwright 流程上传并发布已批准任务。
- 发布后能回查远端状态，不能盲目重试不确定发布。
- 中断后可以恢复且不重复上传。
- 登录验证和平台风控不会被自动绕过。
- 所有代码测试、只读真实数据集成测试和 skill 压力场景通过后，才能标记为生产可用。

## 实施边界

本设计要求一次构建完整端到端架构。当前未提供 NAS/飞书/光合路径、视频规格或生产页面稳定选择器时，相应组件必须以明确的配置错误或任务阻断状态结束，不能用猜测值、空实现或静默跳过伪装成功。

生产发布验收必须在用户已授权的店铺会话和少量测试商品上单独完成。完成代码与 skill 不等于已经通过生产后台验收。
