## Why

第三阶段的文件夹归属控件与图片画廊目前使用两套不同步的状态：用户排除文件夹后，对应图片仍留在画廊和已选素材中；同时“待确认”状态增加了不必要的操作和提交校验负担。需要让文件夹决定直接控制本阶段可见、可选和已选的素材，形成符合实际审查习惯的单一状态模型。

## What Changes

- 删除第三阶段文件夹决定中的“待确认”选项，新候选文件夹默认采用。
- 文件夹决定简化为“采用”和“排除该文件夹”两种状态。
- 文件夹状态变化后，立即重新计算该商品可见候选图片，不等待 Agent 重新生成结果。
- 排除文件夹时，立即移除其候选图片，并同步取消来自该文件夹的已选素材和授权决定。
- 重新采用文件夹时，将其已有候选图片恢复到画廊，但不自动恢复此前取消的图片选择。
- 在界面显示本次同步取消的图片数量，避免用户不知道已选结果发生变化。
- 后端提交规范化和阶段校验接受新的二态模型，并兼容读取历史 `pending` 数据，将其解释为默认采用。
- 更新第三阶段测试计划、自动化测试和操作说明。

## Capabilities

### New Capabilities

- `folder-gallery-sync`: 定义第三阶段文件夹采用/排除的二态模型，以及文件夹决定对候选画廊、已选素材和持久化 JSON 的实时联动行为。

### Modified Capabilities

无。

## Impact

- 主要影响第三阶段前端渲染与状态持久化：`interaction/static/app.js`、相关样式和交互测试。
- 影响 `asset_matching` 阶段输入的后端规范化与校验：历史 `pending` 兼容、文件夹决定和图片决定一致性。
- 需要确保图片候选记录能够稳定关联其来源文件夹；必要时为候选结果补充 `folder_id` 或规范化后的 `folder_path`。
- 不改变共享盘源文件、全局文件夹索引、图片抽样上限、分页策略、第五阶段坑位编排及正式发布授权边界。
