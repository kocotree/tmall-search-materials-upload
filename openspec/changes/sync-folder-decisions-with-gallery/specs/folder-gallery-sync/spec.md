## ADDED Requirements

### Requirement: 文件夹决定使用二态模型
第三阶段 SHALL 只向用户提供“采用”和“排除该文件夹”两种文件夹决定，并 SHALL 将没有显式决定的新候选文件夹视为采用。

#### Scenario: 新候选文件夹默认采用
- **WHEN** 用户第一次打开包含新候选文件夹的第三阶段页面
- **THEN** 文件夹显示为采用状态，并且页面不显示“待确认”选项

#### Scenario: 历史待确认状态兼容
- **WHEN** 页面读取包含 `pending` 文件夹决定的历史任务
- **THEN** 系统将该文件夹解释为采用，且新保存结果中不再写入 `pending`

### Requirement: 文件夹决定实时控制候选画廊
第三阶段 SHALL 在文件夹决定变化后立即重新计算对应商品的可见图片候选、候选数量和分页状态，无需等待 Agent 重新生成结果。

#### Scenario: 排除文件夹立即隐藏图片
- **WHEN** 用户将一个采用中的文件夹改为“排除该文件夹”
- **THEN** 来源于该文件夹的候选图片立即从对应商品画廊中消失

#### Scenario: 重新采用文件夹恢复候选
- **WHEN** 用户将已排除文件夹重新改为“采用”
- **THEN** 该文件夹在当前 Agent 结果中已有的候选图片重新进入画廊

#### Scenario: 过滤后重新计算分页
- **WHEN** 文件夹决定变化导致当前商品的候选图片数量或页数减少
- **THEN** 系统更新候选数量、当前批次图片数量和换批按钮，并将无效页码收敛到最后一个有效页面

### Requirement: 排除文件夹同步取消已选素材
第三阶段 MUST 从已选素材和授权决定中移除所有来源于被排除文件夹的图片。

#### Scenario: 排除包含已选素材的文件夹
- **WHEN** 用户排除的文件夹包含当前已选图片
- **THEN** 系统同步取消这些图片的采用和本次授权，并显示被取消的准确图片数量

#### Scenario: 排除不包含已选素材的文件夹
- **WHEN** 用户排除的文件夹没有当前已选图片
- **THEN** 系统更新画廊但不显示虚假的取消数量

#### Scenario: 重新采用不恢复旧选择
- **WHEN** 用户重新采用此前排除的文件夹
- **THEN** 候选图片可以重新显示，但此前被同步取消的采用和授权状态保持未选

### Requirement: 已选素材区域保持一致
第三阶段 SHALL 让“已选素材”区域只显示当前仍可见且属于采用中文件夹的已选图片。

#### Scenario: 换批保留有效选择
- **WHEN** 用户切换候选图片批次
- **THEN** 所有仍属于采用中文件夹的已选图片继续显示在“已选素材”区域

#### Scenario: 排除后更新已选数量
- **WHEN** 文件夹排除操作同步取消一张或多张已选图片
- **THEN** “已选素材”数量和缩略图列表立即更新

### Requirement: 候选图片具有可审计的文件夹归属
新生成的图片候选 MUST 携带能够与文件夹候选稳定关联的 `folder_id`，并 SHALL 保留来源路径供审查。

#### Scenario: 新任务生成图片候选
- **WHEN** Agent 根据已采用文件夹生成第三阶段图片候选
- **THEN** 每条候选包含对应商品、`folder_id`、来源系统和来源路径

#### Scenario: 历史候选缺少文件夹标识
- **WHEN** 历史任务的图片候选缺少 `folder_id`
- **THEN** 系统尝试通过规范化父路径唯一归属，无法唯一归属时保持候选可见并标记为历史未关联

### Requirement: 提交结果保持跨字段一致
后端 MUST 在保存或提交第三阶段输入时，确保被排除文件夹的图片不会出现在 `asset_decisions` 或 `license_decisions` 中。

#### Scenario: 客户端提交矛盾决定
- **WHEN** 提交内容同时排除了某文件夹并选择了该文件夹中的图片
- **THEN** 后端移除矛盾的图片采用和授权决定，再持久化规范化结果

#### Scenario: 提交采用文件夹的图片
- **WHEN** 已选图片属于采用中的文件夹且通过现有图片校验
- **THEN** 后端保留其采用决定，并生成对应的本次授权决定
