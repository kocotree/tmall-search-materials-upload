## Context

第三阶段当前同时渲染文件夹归属列表和图片候选画廊，但两者只共享初始 Agent 结果，不共享实时派生状态。文件夹下拉框变化只写入 `folder_decisions`，图片画廊继续使用静态 `asset_candidates`；因此排除文件夹不会立刻移除图片，也不会清理已选和授权记录。

业务已经确定采用更简单的审查模型：扫描命中的文件夹默认进入候选范围，用户只需要排除不属于本商品或不希望使用的文件夹。候选池仍由 Agent 在读取确认文件夹后生成，前端联动只在当前结果已有候选图片范围内进行，不访问共享盘。

## Goals / Non-Goals

**Goals:**

- 将文件夹决定收敛为“采用”和“排除”二态。
- 在同一页面内让文件夹决定即时控制候选、分页、已选素材和持久化决定。
- 确保提交到 Agent 的 `folder_decisions`、`asset_decisions` 和 `license_decisions` 一致。
- 保持历史任务可打开，并将历史 `pending` 安全解释为默认采用。
- 对自动取消已选素材提供明确、可追溯的用户提示。

**Non-Goals:**

- 不在浏览器中重新扫描共享盘或重新执行 100 张比例抽样。
- 不自动恢复被排除前的图片选择。
- 不改变图片适用性、裁剪、坑位编排、上传和正式发布流程。
- 不改变全局文件夹索引及其增量维护策略。

## Decisions

### 1. 文件夹状态使用显式二态，未持久化即表示采用

界面只显示“采用”和“排除该文件夹”。为了避免为大量默认采用文件夹写入冗余记录，前端派生状态将“没有决定记录”解释为采用；仅当用户排除时必须持久化 `rejected`。提交规范化可以输出全部文件夹的显式二态决定，确保 Agent 获得完整快照。

备选方案是继续保存每个默认采用文件夹的 `confirmed` 记录。该方案提交数据更直观，但初次打开页面会产生大量无用户操作的变更，且增加草稿噪声，因此不作为前端内部状态的唯一要求。

### 2. 候选图片以稳定的来源文件夹标识关联

新生成的 `asset_candidates` 应携带 `folder_id`，并保留 `folder_path` 作为可审计信息。前端使用 `(product_id, folder_id)` 判断候选是否可见，不使用模糊字符串包含关系。

为兼容已有任务，缺少 `folder_id` 的历史候选可使用规范化绝对路径和“最长已确认父路径”做一次只读归属推导；无法唯一归属的候选继续显示并标记为历史未关联，避免静默丢失。

备选方案是始终根据 `source_path.startsWith(folder_path)` 判断。该方案在路径大小写、分隔符、相邻同名前缀和嵌套文件夹下容易误判，因此只作为历史迁移兜底。

### 3. 画廊由原始候选和当前文件夹状态派生

页面保留不可变的原始 `asset_candidates`，每次文件夹状态变化后重新计算：

1. 当前商品采用中的文件夹集合；
2. 可见且去重后的候选图片；
3. 当前页码和每批数量；
4. 已选素材中仍属于可见候选的部分；
5. 授权决定中仍属于已选素材的部分。

如果过滤后当前页超出范围，页码收敛到最后一个有效页面。这样“候选数量、分页、换一批、已选数量”由同一派生结果驱动。

### 4. 排除文件夹时同步清理图片决定

当文件夹从采用切换为排除时，前端在一次同步操作中：

- 持久化文件夹排除决定；
- 从可见画廊移除对应图片；
- 从 `asset_decisions` 移除对应已选图片；
- 从 `license_decisions` 移除相同图片授权；
- 显示“已同步取消 N 张已选素材”的非阻断提示。

重新采用文件夹只恢复候选图片，不恢复此前选择和授权，防止用户无意重新批准素材。

### 5. 后端在提交边界再次执行一致性收敛

前端联动提供即时体验，后端 `_normalize_stage_values` 仍必须根据最终文件夹决定过滤 `asset_decisions` 和 `license_decisions`。这样即使旧客户端或手工 JSON 提交了矛盾状态，也不会让被排除文件夹的图片进入下一阶段。

历史 `pending`、缺省或未知空值在读取时按采用处理；新提交不得保存 `pending`。

## Risks / Trade-offs

- **历史候选缺少 `folder_id`，可能无法唯一映射** → 使用规范化最长父路径兜底并显示历史未关联提示；新结果强制写入 `folder_id`。
- **一次排除可能取消很多已选素材** → 在动作发生后显示准确数量；不自动恢复，避免隐式授权。
- **多个嵌套文件夹可能指向同一图片** → 候选仍按 SHA-256/资产 ID 去重，归属优先使用生成时写入的稳定 `folder_id`。
- **前端状态与提交状态可能被手工篡改** → 后端规范化再次按最终文件夹决定收敛。
- **过滤后页码失效** → 每次重新派生画廊时夹紧页码并重新计算按钮状态。

## Migration Plan

1. 为新生成的图片候选补充稳定 `folder_id`。
2. 在前端加入二态文件夹状态派生和画廊联动函数。
3. 在后端规范化中加入历史 `pending` 兼容和最终一致性过滤。
4. 使用历史任务验证缺少 `folder_id` 时的路径兜底。
5. 更新测试计划和操作文档后重新启动交互服务。

回滚时可恢复旧版前端三态下拉框；新增的 `folder_id` 字段为向后兼容字段，旧代码会忽略。已经保存的 `rejected`/`confirmed` 决定仍可被旧版读取。

## Open Questions

无。业务行为已经明确：默认采用、只允许排除、排除立即同步取消、重新采用不恢复旧选择。
