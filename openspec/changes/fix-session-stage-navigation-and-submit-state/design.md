## Context

现有前端在脚本启动时把 `currentStageId` 固定为第一个导航按钮，然后立即激活第一阶段。虽然会话 API 已返回 `session.current_stage` 和全部阶段 revision/status，启动流程没有使用这些信息，因此历史任务刷新后总会落到阶段 01，导航中的其他阶段也继续显示模板默认状态，直到用户逐个打开。

阶段渲染器还会通过隐藏 JSON 控件回写默认决定。通用写入函数无条件派发 `input` 事件，使“数据水合/默认值规范化”被误判为用户编辑并触发自动保存。保存请求进行时，`persistStage` 对后续保存或提交直接 `return`，所以用户的提交意图可能没有反馈地消失。

## Goals / Non-Goals

**Goals:**

- 历史任务刷新后进入服务端记录的当前阶段，并正确展示全部阶段状态。
- 页面水合和组件初始化保持幂等，不产生 dirty 状态或新 revision。
- 保存进行期间的提交意图不会丢失，并向用户显示确定的处理状态。
- 已锁定阶段给出明确原因与前往当前阶段的操作。
- 保持现有任务目录、会话 JSON 和阶段 API 的兼容性。

**Non-Goals:**

- 不改变 Agent 认领、生产授权和上传安全门禁。
- 不允许覆盖 `completed`、`processing` 或已认领的 handoff。
- 不引入新的前端框架或外部状态管理依赖。
- 不迁移、删除或重写历史 revision。

## Decisions

### 1. 先加载会话快照，再激活初始阶段

有 `session_id` 时，启动流程先获取会话 API，校验 `session.current_stage` 是否属于已知阶段，再激活该阶段；无效或缺失时回退到第一阶段。会话快照同时用于更新所有导航项的 revision/status。

选择复用现有会话 API，而不是增加本地缓存或从各阶段 API 逐个推断，避免多请求之间出现状态不一致。

### 2. 区分静默水合和用户编辑

隐藏 JSON 控件写入接口增加“是否派发用户输入事件”的语义。表单水合、结果组件首次构建和默认值规范化使用静默写入；只有用户点击、选择、拖拽、输入等交互才标记 dirty 并触发自动保存。

写入前还应比较规范化后的新旧值；值没有变化时不得派发事件。这样可以同时防止重复 revision 和无意义的 DOM 更新。

### 3. 将持久化从布尔锁改为单飞请求加待处理意图

同一阶段同一时间仍只允许一个持久化请求。当请求进行中：

- 后续“保存草稿”可合并为一次最新值保存。
- 后续“提交给 Agent”记录为优先级更高的待处理意图。
- 当前保存成功后重新读取最新表单值和 revision，再执行待处理提交。
- 阶段切换或 session 变化时取消旧意图，继续使用现有 generation/request identity 防止跨阶段回写。

不采用并行提交，因为会扩大 revision 冲突；也不继续静默 `return`，因为用户无法判断操作是否生效。

### 4. 锁定状态必须可解释

已完成、已提交或处理中阶段保留只读展示，但底部操作区必须显示锁定原因。历史任务打开到非当前的已完成阶段时，提供“进入当前阶段”入口；不通过重新启用按钮来绕过服务端状态机。

### 5. 浏览器验收以无副作用为核心

回归测试除检查页面文字外，还必须比较打开前后的 revision、input SHA-256 和 handoff 状态。仅查看阶段不得生成 revision；保存与提交竞态测试必须证明最终产生一次有效提交，且不存在跨阶段写入。

## Risks / Trade-offs

- [启动时多一次会话等待可能让首屏稍晚] → 先显示加载状态，拿到会话快照后一次性激活正确阶段，避免先显示错误阶段再跳转。
- [待处理提交使用了保存结束后的最新表单值] → 页面明确显示“正在保存，随后提交”，并在实际提交前重新执行完整客户端和服务端校验。
- [旧渲染器依赖初始化时派发 `input`] → 逐个审计图片审查、坑位编排、文件夹与画廊渲染器，为默认值补充显式静默持久化测试。
- [历史任务存在不支持的 current_stage] → 记录可见警告并安全回退阶段 01，不修改原 session 文件。

## Migration Plan

1. 先增加状态初始化和持久化竞态单元测试，锁定现有失败行为。
2. 重构启动、水合和 JSON 控件写入，再更新图片审查与坑位渲染器。
3. 增加历史会话真实浏览器验收，确认刷新不产生新 revision。
4. 保持 API 和文件 Schema 不变，可直接回滚前端静态资源；无需数据迁移。

## Open Questions

无阻塞问题。实现时可以选择是否把当前阶段同步到 `stage` 查询参数，但这不是本变更的验收前提。
