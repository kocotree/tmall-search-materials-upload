## Context

当前第三阶段已经能从任务级候选池中选择任意数量图片，但图片卡片没有把宽高、相对推荐分辨率、比例、文件大小和裁剪可行性转化为用户可理解的状态。第四阶段只注册了 `image_review / CropDecision` 名称和三个底层必填字段，没有实际扫描器、裁剪预览、决定控件或派生文件生成逻辑；第五阶段也尚未消费经过图片合规确认的输出。

千牛给出的业务要求同时包含软建议和组合约束：每篇 3–9 张、推荐使用 3:4 或 1:1、推荐尺寸分别达到 1440×1920 和 1440×1440，同一篇不得混合比例。第三阶段的职责是选择内容合适的源素材，第五阶段才决定每个坑位的图片组合，因此不能在第三阶段依据尚未确定的坑位比例淘汰所有可裁剪图片。

现有真实任务中选中的 9 张图片没有一张可以同时直接满足目标比例和推荐尺寸，其中 2 张高分辨率图片适合裁剪，其他图片需要软警告或人工判断。这证明只采用“第三阶段不满足即禁止”的方案会丢失有效素材。

## Goals / Non-Goals

**Goals:**

- 在第三阶段提供低成本、无副作用的尺寸和比例预检。
- 在第三阶段显示原始宽高、每个目标比例是否达到推荐分辨率、原始比例、文件大小和大小上限状态。
- 在第四阶段建立从已选原图到确认输出的完整人工裁剪工作流，并自动提供 1:1 和 3:4 两种初始裁剪框。
- 让推荐分辨率保持策略可配置的软提示，同时支持业务将其升级为阻断。
- 保证所有裁剪均为任务目录派生文件，源素材只读且可追溯。
- 让第五阶段只使用第四阶段确认输出，并强制每坑 3–9 张和比例一致。
- 支持历史任务按第三阶段 revision 补建第四阶段结果。

**Non-Goals:**

- 不在第三阶段提前决定坑位分组。
- 首个 MVP 不执行独立图片压缩，也不调用 AI、生图、扩图或超分辨率服务，只预留图片压缩和 AI 裁剪建议接口。
- 不自动放大低分辨率图片，也不跳过用户裁剪确认。
- 不覆盖共享盘图片，不改变第三阶段最多 100 张的候选抽样策略。
- 不处理视频规格和视频裁剪。

## Decisions

### 1. 使用“第三阶段提示、第四阶段处理、第五阶段强校验”的分层模型

第三阶段基于候选已有的图片检测元数据计算预检标签，只对确定不可用的文件硬拦截。比例不匹配、推荐尺寸不足和文件大小超限仍允许采用，因为这些图片可能通过人工裁剪、后续压缩能力或业务软策略继续使用。第三阶段只展示状态和收集选择，不生成任何派生图片。

第四阶段把每个源图片转换为一个明确的输出决定。第五阶段不再直接引用第三阶段原图，而是引用第四阶段确认输出。

备选方案是在第三阶段直接禁止所有不符合推荐值的图片。该方案实现简单，但会把“建议”错误升级为强制规则，且无法表达可裁剪状态，因此不采用。

### 2. 任务级策略快照是三个阶段的唯一规则来源

进入第四阶段前，将运行时图片策略复制为任务级快照并记录 SHA-256。策略至少定义：

- 允许格式；
- 允许输出比例及比例容差；
- 每个比例的推荐宽高；
- 低于推荐尺寸是 `warning` 还是 `blocking`；
- 最大图片大小；
- 裁剪输出格式、质量和派生目录限制。

示例策略将 `max_image_size_mb` 设为 `20`，并统一按 `20 × 1024 × 1024` 字节计算边界；页面按 MB 格式化展示，原始 `size_bytes` 保留用于精确校验。

第三阶段预检、第四阶段扫描和第五阶段校验都读取同一快照。策略缺失时阻断结果生成，避免页面和后端产生不同判断。

### 3. 第四阶段结果由“源图片检测 + 用户决定 + 可选派生输出”组成

每张已选图片生成结构化记录：

- `asset_id`、第三阶段 revision；
- 源路径、源 SHA-256、宽高、比例和文件大小；
- 对 1:1/3:4 两个目标比例计算的最大内接尺寸及“达到推荐 / 低于推荐”结果；
- `preflight_status` 与原因码；
- 用户选择的 `target_ratio`；
- `action`: `direct`、`crop`、`candidate_only` 或 `excluded`；
- 系统计算的 1:1/3:4 初始裁剪框和人工调整后的裁剪框；
- 最终确认裁剪框；
- 输出路径、输出尺寸、输出 SHA-256；
- 策略版本和确认时间。

直接使用仍产生“确认输出记录”，但不复制原图；裁剪决定生成任务目录派生文件。第五阶段统一消费确认输出记录。

### 4. 为每张图片确定性计算双比例初始裁剪框

系统对 1:1 和 3:4 分别计算最大内接居中框。设原图尺寸为 `W×H`，目标宽高比为 `r`：

- 当 `W/H > r` 时，使用完整高度：`crop_h = H`、`crop_w = floor(H*r)`、`x = floor((W-crop_w)/2)`、`y = 0`；
- 当 `W/H <= r` 时，使用完整宽度：`crop_w = W`、`crop_h = floor(W/r)`、`x = 0`、`y = floor((H-crop_h)/2)`。

两个初始框都转换为 `[0,1]` 规范化坐标并写入第四阶段结果。页面维护每个目标比例各自的人工调整状态；用户切换比例时不会丢失另一比例的调整。拖动和缩放始终锁定目标比例，并限制在原图边界内。

备选方案是只在用户选定比例后计算一个框。该方案减少少量初始数据，但用户无法快速比较 1:1 与 3:4 的主体保留效果，因此不采用。

### 5. 裁剪预览与派生生成分离

浏览器使用低分辨率预览和规范化裁剪框进行交互，避免每次拖动都读写共享盘大图。用户确认后，后端才从原图按最终像素裁剪框生成高质量派生文件。

裁剪框在 JSON 中使用规范化坐标，同时记录最终像素坐标，便于重放和审计。生成前再次验证源 SHA-256，避免源文件变化后沿用旧预览。

### 6. 首版只实现人工裁剪，AI 仅保留接口

MVP 不加载模型、不调用外部 AI，也不执行生图。人工裁剪所需的双比例初始框由确定性几何算法生成。

代码预留 `CropSuggestionProvider` 契约，输入至少包含源资产 ID、源 SHA-256、预览或受控源引用、原图尺寸和目标比例；输出包含规范化裁剪框、提供方 ID、模型/版本和置信度。接口返回值只作为可选建议，未来接入后仍必须由用户确认。

首版只实现空提供方和测试替身，用于稳定接口契约；未配置提供方是正常状态，页面不展示 AI 操作。

### 7. 图片压缩只预留派生输出接口

第三阶段使用索引中的 `size_bytes` 显示格式化图片大小，并与任务策略中的最大图片大小比较。超过上限时标记 `IMAGE_SIZE_EXCEEDED / 需要压缩`，但不在第三阶段读取并重写共享盘原图。

代码预留 `ImageCompressionProvider` 契约，输入至少包含源资产 ID、源 SHA-256、目标格式、质量策略、最大输出字节数和任务派生目录；输出包含任务目录内的派生路径、输出字节数、输出 SHA-256、提供方 ID 和版本。首版只实现空提供方和测试替身，不展示压缩按钮，也不把“接口存在”误报为“压缩能力可用”。

压缩结果未来接入后仍需通过与裁剪结果相同的路径边界、来源链和人工确认校验。未产生满足大小上限的输出时，第五阶段拒绝超限图片。

### 8. 比例一致性和文件大小在第五阶段按确认输出校验

第四阶段为每张确认输出确定一个比例。第五阶段按坑位检查：

- 图片数量为 3–9；
- 全部图片来自当前第四阶段 revision；
- 比例集合大小为 1；
- 每个确认输出不超过任务策略中的最大图片大小；
- 所有图片状态为确认可用。

这样既允许一个商品同时拥有 3:4 和 1:1 输出，又确保单个坑位不混用。

### 9. 历史任务使用显式补建而不是静默迁移

第三阶段已提交但第四阶段无结果时，Agent 运行图片审查准备命令，对当前选择逐张读取并生成第四阶段 `review-context`。页面显示“待 Agent 扫描 N 张”，不要求用户填写 `policy_path` 或原始 JSON。

若第三阶段重新提交，第四阶段现有结果标记为过期；派生文件保留作审计但不能进入第五阶段。

## Risks / Trade-offs

- **推荐尺寸被业务误认为平台强制限制** → 策略中显式区分 `warning` 与 `blocking`，页面使用不同视觉状态和文案。
- **文件大小超限被误认为当前已经可以压缩** → 第三阶段只显示“需要压缩”，首版不展示压缩按钮；第五阶段对未处理的超限输出保持阻断。
- **最大居中框可能裁掉偏离中心的商品主体或文字** → 同时展示两个比例预览并允许用户移动、等比例缩放后确认。
- **大图预览和裁剪导致页面缓慢** → 交互使用现有任务级缩略图，确认时才读取原图生成派生文件。
- **源文件在确认期间发生变化** → 生成派生文件前重新核对源 SHA-256，不一致时要求重新扫描。
- **第三阶段选择变化导致旧裁剪继续被使用** → 所有结果绑定第三阶段 revision，第五阶段拒绝过期输出。
- **低分辨率图片裁剪后更小** → 明确显示输出尺寸和警告；不把裁剪描述为提升分辨率，不自动执行 AI 放大。
- **未来 AI 或压缩接口实现与人工数据结构分叉** → AI 建议复用规范化裁剪框契约，压缩输出复用派生文件来源链与人工确认流程。

## Migration Plan

1. 扩展任务级图片策略 Schema，加入最大图片大小，并提供符合千牛建议值的示例策略。
2. 在第三阶段候选数据和卡片中增加原始宽高、目标比例推荐分辨率比较、原始比例、文件大小、预检状态及筛选标签。
3. 增加第四阶段准备器，读取当前第三阶段提交和策略快照，生成图片审查结果。
4. 实现 1:1/3:4 双比例初始框、原图/裁剪预览、人工拖动缩放和结构化决定，并加入不调用外部服务的 AI 建议器接口和图片压缩接口。
5. 实现安全派生文件生成、来源链记录和过期检测。
6. 修改第五阶段只消费第四阶段确认输出，并加入数量与比例一致性校验。
7. 使用当前历史任务补建第四阶段结果，再使用新任务验证完整流程。

回滚时可隐藏新的第四阶段可视化组件并停止第五阶段消费派生输出；任务目录中的派生文件和审计 JSON 保留，不回写共享盘。

## Open Questions

无。首个 MVP 已确定只交付人工裁剪和双比例初始框；图片压缩与 AI 裁剪仅预留接口。
