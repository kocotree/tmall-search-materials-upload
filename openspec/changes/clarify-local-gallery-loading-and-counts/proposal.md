## Why

第三阶段已经在后端区分“本机加载候选图片”和“最终选图交给 Codex”，但页面仍复用底部交接按钮并显示“Agent 正在准备图片”，让用户误以为文件夹确认会触发 Codex。当前文件夹卡片也缺少素材数量，图片准备进度又把“已检查数”和“最终去重候选数”混称为“已准备”，导致运行中的 `284` 与完成后的 `286/300` 难以解释。

## What Changes

- 将“确认文件夹并加载图片”改为文件夹审查区域内的独立本机操作按钮，放在候选文件夹下方、候选图片上方；该操作只启动本地 gallery job，绝不创建 handoff。
- 保留页面底部“确认选图并提交给 Codex”作为唯一素材交接按钮，仅在图片选择步骤可用并创建最终选图 handoff。
- 移除本机图片加载期间的 Agent/Codex 文案，明确显示本机扫描、检查、去重和候选生成状态。
- 为每个候选文件夹展示素材数量及统计状态，区分原始递归发现数量和去重后的有效数量；计数只允许枚举文件元数据，不读取、解码或哈希图片内容。
- 分离“发现路径数”“计划检查数”“已检查数”“检查失败数”“内容重复数”和“最终可展示候选数”，完成状态不得继续显示中间进度快照。
- 明确每商品 100 张是检查上限，不保证最终唯一候选数为 100；相同内容的文件按商品内 SHA-256 去重后必须报告差额原因。
- 自动化只覆盖简单的单元、接口、状态和静态页面契约测试；真实 NAS、Windows 身份、长时间加载、刷新/中断恢复和复杂人工交互由用户验收。

## Capabilities

### New Capabilities

- `local-gallery-review-controls`: 定义第三阶段本机文件夹确认、文件夹素材计数、候选图片加载进度、最终去重统计和唯一 Codex 交接按钮的可观察行为。

### Modified Capabilities

无。

## Impact

- 影响第三阶段交互页面的按钮布局、状态文案、文件夹卡片和进度展示。
- 影响 gallery job 的进度/结果字段以及文件夹候选或计数缓存的数据结构。
- 影响本机 `prepare-gallery` API 与最终素材提交 API 的交接断言，但不改变最终 handoff 身份校验和后续确定性坑位编排。
- 不读取或修改 NAS 原图，不引入 AI 图片选择，不扩大 Codex 权限，也不要求自动化执行复杂的真实环境交互测试。
