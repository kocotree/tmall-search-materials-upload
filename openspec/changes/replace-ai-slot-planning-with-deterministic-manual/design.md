## Context

当前非 AI 分支继承了独立的 `image_review` 用户阶段、“AI/人工共用唯一坑位草稿”和第五阶段三子页面。素材选择卡已经展示大部分原图与合规信息，独立图片适用性页面又要求用户做一次“候选/排除”决定；但最终裁剪仍必须等坑位比例确定后才能进行。第二阶段已经掌握后台缺失坑位数，因此可以在素材选择阶段对采用图片自动增量预检，随后直接确定性编排。

本设计只取消坑位编排中的 AI。标题和描述仍属于独立的 AI 建议边界，并继续由用户最终确认。历史任务可能保存 `agent_assisted`、`rules` 或 `agent_assisted_with_rules_fallback` 草稿，必须保留审计和恢复能力。

## Goals / Non-Goals

**Goals:**

- 去掉新任务独立的图片适用性用户页面，但完整保留自动合规检查、安全门禁和审计快照。
- 相同素材选择、缺失坑位数和策略版本始终产生相同坑位草稿。
- 在素材选择阶段实时告诉用户当前选图可以形成多少完整坑位。
- 尽量覆盖更多后台缺失坑位，同时确保每坑 3–9 张、同坑统一比例和图片跨坑唯一。
- 自动结果允许人工加删、调序、改比例和重新编排。
- 原第五阶段 `slots_copy` 成为素材选择后的下一个可见阶段，并收敛为裁剪压缩、AI 文案两个递进子页面。
- 保留历史草稿、处理输出、文案和生产门禁。

**Non-Goals:**

- 不根据画面语义识别正面、侧面、场景或自动生成主题聚类。
- 不保证一次任务填满后台全部缺失坑位。
- 不取消 AI 标题和描述生成。
- 不删除图片合规检测，不改变 Pillow 处理实现或生产安全门禁。
- 不执行真实上传。

## Decisions

### 1. 图片适用性检测合并到素材选择阶段

新任务不再渲染 `image_review` 导航、页面或第二次候选决定。用户在素材选择阶段采用图片后，后台只检查本次采用项，并在原卡片中回显：

- 源文件可读性、格式、宽高、比例、大小和 SHA-256；
- 重复身份；
- `1:1 / 3:4` 最大内接输出与最低/推荐分辨率；
- 是否需要压缩及当前压缩提供方是否可用。

检查结果以任务级 snapshot 绑定素材选择 revision、策略 SHA 和提供方版本，可以内部复用现有 suitability 数据结构，但不再成为独立用户阶段。该阶段只计算候选框，不生成派生图。

1–2 张有效图片允许保存选择草稿，但主动作禁用并显示还差几张。这样既不丢用户选择，也不会把无法确认的空坑位带到下游。

### 2. 素材选择提交时生成唯一确定性草稿

素材选择按钮改为“确认选择并自动编排坑位”。服务端只在每个提交商品至少有 3 张通过预检的唯一图片时，同步计算坑位草稿并写入 `current-slot-plan.json`，来源为 `deterministic`，随后进入 `slots_copy` 第一页。

不采用“进入下一阶段后再点击自动编排”，因为用户已经完成影响编排的最后一次选择；同步生成能让阶段交接具有单一结果，也不需要 Agent 轮询。

### 3. 最大化完整坑位数，而不是最小化坑位数

对每个商品：

```text
N = 去重、未阻断且用户采用的图片数
M = 后台缺失坑位数
K = min(M, floor(N / 3))
A = min(N, K × 9)
```

`K=0` 时不创建完整坑位。`K>0` 时将前 `A` 张稳定排序图片平均分配：每坑先取 `floor(A/K)` 张，前 `A mod K` 个坑位各多 1 张。该公式天然保证每坑 3–9 张。

选择“最大化完整坑位数”是因为当前业务目标是补充尽可能多的搜推素材坑位；例如 9 张且至少缺 3 坑时生成 `3+3+3`，而不是单坑 9 张。若业务以后更重视单坑丰富度，可把目标函数版本化，而不是修改历史结果。

### 4. 用户顺序优先，来源稳定交错

用户在素材选择阶段的 `selection_order` 是质量优先级。编排器先按该顺序建立各已确认来源文件夹队列，再以稳定来源键轮询交错。这样既保留用户优先级，也避免一个坑位被单一来源连续占满。

超过 `K×9` 的尾部素材不丢弃，写入商品级 `unused_assets[]`，原因记为 `MISSING_SLOT_CAPACITY_REACHED`。

### 5. 比例选择使用可解释的字典序评分

对每个初始坑位分别评估 `3:4` 和 `1:1`。比例必须对坑内全部素材可行，随后按以下字典序从优到劣排序：

1. 原生匹配数量多；
2. 达到推荐分辨率数量多；
3. 平均裁剪保留率高；
4. 需要压缩数量少；
5. 固定优先级 `3:4` 先于 `1:1`。

评分组成与策略版本写入坑位。若初始组没有公共比例，编排器按稳定顺序尝试与未分配或相邻坑位素材交换；无法修复时不生成非法坑位，将相关素材退回未使用池并要求人工调整。

不使用随机数、当前时间、文件枚举顺序或模型判断。

### 6. 坑位处理第一页合并坑位审核与图片处理

新导航只有：

1. 图片裁剪和压缩
2. AI 生成标题和描述

第一页顶部显示自动坑位、未使用候选和人工编辑操作。坑位未确认时裁剪区隐藏或禁用；确认精确 revision 后在同一页面展开裁剪区。任何坑位成员、顺序或比例变化都会撤销确认，并按现有失效范围清理派生输出和文案。

这样保留人工编排能力，但不再把编排呈现成独立子阶段。

### 7. AI 文案保持独立边界

文案请求只读取最终处理后的有序图片和允许的商品事实。响应只能建议标题、描述和备注，不能修改坑位、图片、比例或处理参数。失败时保留所有图片输出，允许重试或人工录入。

### 8. 可见阶段顺序、Schema 与历史兼容

新任务的可见阶段从 `asset_matching` 直接进入 `slots_copy`。内部 ID 保持稳定，但导航序号按新任务的八个可见阶段重新计算；历史 session 继续按持久化 stage ID 和 revision 恢复，不依赖旧的显示序号。

`current-slot-plan.json` 增加：

- `decision_source: deterministic | manual | manual_override`
- `planning_strategy_id`
- `planning_strategy_sha256`
- `missing_slots`
- `score_components`
- `unused_assets[]`

新任务不创建坑位 Agent request/response。历史 `04-image-review`、AI/规则字段只读保留；兼容的历史 suitability 记录可迁移到素材选择预检快照。显式重新编排写入新 revision，人工编辑写入 `manual_override`。历史三页面状态通过持久化 `workflow_state` 映射到两个页面，不移动或删除旧文件。

## Risks / Trade-offs

- [没有语义聚类，可能把相似构图放在同一坑位] → 来源交错降低集中度，并在第一页保留人工换图和调序。
- [素材选择时检查共享盘图片可能造成等待] → 只检查采用项、逐卡增量更新并按素材身份缓存；禁止重新遍历全部共享盘。
- [最大化坑位数会使许多坑位只有 3 张] → 页面明确展示分配数量；用户可删除坑位或把图片合并到其他坑位。
- [后台缺失坑位数陈旧] → 草稿绑定采集 revision；进入 dry-run 前继续复查，发生变化时阻断而非自动扩展。
- [比例贪心交换可能无法找到存在的复杂组合] → 保持算法可解释和有界；失败素材回到候选池，由人工处理，不引入不可预测搜索。
- [移除独立 stage 和从三页面迁移到两页面可能造成旧 URL/状态不一致] → 以服务端 stage ID、revision 和 `workflow_state` 为权威，增加历史 session 浏览器回归。

## Migration Plan

1. 在非 AI 分支增加 selected-asset preflight 契约，复用检测器并固定缓存/失效测试。
2. 在素材选择卡接入增量预检、数量提示和 1–2 张提交门禁。
3. 增加策略版本和确定性编排器，以单元测试固定分配结果。
4. 接入素材选择提交后的自动草稿生成，停止新坑位 Agent 请求并移除新任务的独立 `image_review` 导航。
5. 将 `slots_copy` 导航改成两页，迁移现有 compose 状态到第一页的坑位审核区。
6. 更新历史 stage、草稿、人工覆盖、失效范围、文案请求和恢复说明。
7. 使用历史 session 与一个可读素材的新 session 做浏览器验收。
8. 回滚时切回原 AI 分支；不删除本分支生成的任务数据。

## Open Questions

无阻断问题。当前固定约定为：最大化完整坑位数、同分时优先 `3:4`、仅取消坑位 AI 而保留文案 AI。若业务希望优先每坑 6 张或同分优先 `1:1`，应在实施前修改策略版本与本设计。
