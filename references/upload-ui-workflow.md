# Playwright 后台流程

## 会话与配置

- 用户自行登录天猫并处理验证码、短信、扫码和风控。
- CLI 通过运行时 `--cdp-url` 连接用户已启动的 Chromium 会话；不持久化会话秘密。
- 每次导出、补采和发布前读取页面可见店铺名，必须与目标店铺完全一致。
- 生产选择器通过版本库外的 YAML 文件传入。缺少任何必需键立即停止。

## 导出

1. 为本次任务创建独立时间戳目录；输出目录必须不存在或为空。
2. 导出前读取页面可见店铺名并与目标店铺精确匹配，同时检测验证码、扫码和风控页面。
3. 用 `--report basic` 触发基础素材下载，不从公共下载目录猜测“最新文件”。
4. 按 `run_id` 保存到 `basic/` 子目录，记录原始文件名、下载时间、SHA-256、数据行数和 schema 校验结果，不覆盖历史批次。
5. 写入 `source-files.json` 与 `export-manifest.json`。清单保存准确店铺、商品状态筛选条件、报表状态和原因码。

基础素材 XLSX 必须校验 `商品ID`、`商品标题`、`商品白底图`、`短标题`（或标准化别名）。Excel 可见空单元格按缺失处理，不得把底层样式或读取工具的展示值当作业务值。

搜推页的“导出数据”是经营指标，不是商品素材与坑位真相源，不得用于自动判定完整或进入生产批准。推广素材必须按精确商品 ID 从实时 DOM 采集。高价值商品页面会明确显示目标发布容量 9 篇和当前发布篇数；每篇素材读取远端素材 ID及可见异常状态。页面未展示固定编号坑位时，只记录 `目标容量`、`当前素材数` 和 `缺失数量`，`空坑位` 保持未知，禁止编造 1–9 的空坑编号。

## 补采

先选择“商品分类 → 搜推高价值”，串行扫描全部分页。每页读取商品 ID、明确的目标容量、当前发布篇数、远端素材 ID 和可见状态，跨页按商品 ID 去重，并立即写入 CSV 与 checkpoint。对目标容量不明确、解析失败或状态异常的商品，再按精确商品 ID 搜索补采。素材表容器或字段不存在时返回 `SELECTOR_INVALID`：商品 eligibility 保持 `eligible`，受影响商品进入 `needs_manual_review`，未知字段保持未知。

## 发布

1. 验证 manifest schema、总哈希和目标店铺；旧 manifest 包含有效期时继续兼容校验。
2. 重算当前 item 的媒体、标题、描述、动作和坑位内容。
3. 按商品首次出现顺序分组并精确搜索商品 ID；同一商品后续坑位复用当前商品行，分别核对目标空坑位，并保存各坑位发布前该商品全部远端素材 ID 集合。只有页面上下文失效时才重新进入列表和搜索。
4. 根据批准类型选择图文或视频；图片以包含 SHA 前缀和随机后缀的短唯一名称本地上传并精确回选，正文兼容普通编辑器与 Cangjie 代理 textarea。
5. 仅按 `publisher_ok_clk` 或明确“提交发布/发布”定位最终发布按钮，写入 pre-publish checkpoint 后点击一次；禁止按通用“确认/确定”文字点击。
6. 返回商品列表，重新读取同商品全部远端素材 ID。旧集合必须完整保留且只新增一个 ID；用该集合差异记录新素材及其当前显示位置，不假设原坑位位置稳定。

发布按钮出现前的瞬时页面或网络错误在首次失败后最多重试 3 次，每次重试前原地关闭未发布表单；重试耗尽则跳过当前 item 并继续。店铺、人机验证、批准身份等整批安全异常仍立即停止。

发布后超时、出现二次确认、旧远端 ID 消失或新增 ID 不是恰好一个时进入 `publish_uncertain` 并暂停批次。禁止再次点击发布；先执行远端核验。

## 选择器原则

优先 `data-testid`、稳定 `data-*`、固定字段属性和 ARIA role/label。禁止用屏幕坐标作为常规实现。页面变化只修改 Page Object 或运行时配置，不把选择器写入业务规则。
